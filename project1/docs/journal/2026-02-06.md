# Development Journal - 2026-02-06

## Phase 5: Config-Driven Multi-LLM Provider System

### Goal
Move provider definitions from hardcoded Python dict to `config.yaml` so new providers can be added with zero code changes.

### Changes

**config.yaml:**
- Added `providers` section with 8 entries: moonshot, kimi, nvidia, qwen, glm, deepseek, openai, gemini
- Each provider defines: `api_key_env`, `base_url`, `default_model`, `client_type`
- `client_type` defaults to "openai"; only Gemini uses "gemini"
- Simplified `llm` section: removed `api_key_env`, `model` now optional (empty = use provider default)
- Updated fallback chain: `[moonshot, nvidia, gemini]`

**config.py:**
- Added `ProviderConfig` dataclass
- Removed `api_key_env` from `LLMConfig`
- Added `providers: dict[str, ProviderConfig]` to `Config`
- Added `get_provider()` helper with error messages listing available providers
- `load_config()` now parses providers section and validates all provider references

**llm_client.py:**
- Deleted `PROVIDER_CONFIGS` hardcoded dict (was 20 lines)
- `create_single_client()` now takes `ProviderConfig` instead of looking up from dict
- `create_fallback_client()` now takes `Config` object, resolves providers internally
- `GeminiAPIClient` now accepts `api_key` directly (consistent with `OpenAICompatibleClient`)
- Removed `create_llm_client()` (was a thin wrapper, no longer needed)

**main.py:**
- Simplified LLM client creation: `create_fallback_client(config)` (one call)
