## Bug Fixes (Post-Review)

User reported that relevant papers were not being identified correctly. Investigation revealed:

### Bug 1: Substring matching for project acronyms
- **Problem**: "WST" matched inside "JWST" due to substring matching
- **Fix**: Changed to word-boundary regex matching in `check_project_match()`
- **Code**: `pattern = r'\b' + re.escape(acronym.lower()) + r'\b'`

### Bug 2: Flat prefilter scoring
- **Problem**: All primary category papers got 6.0, project matches didn't boost enough
- **Fix**: New scoring in skip-llm mode:
  - Project + primary category: 8.5 (above most_relevant_threshold)
  - Project only: 7.5
  - Primary category only: 6.0
  - Secondary only: 4.0

### Bug 3: Tier assignment logic
- **Problem**: Project match + primary category didn't guarantee "Most Relevant"
- **Fix**: Added explicit check: `if project_match and primary_category_match: return Tier.MOST_RELEVANT`

### Results After Fix
Papers with tracked projects (DES, KiDS, ACT, JWST) in primary categories now correctly get "Most Relevant" tier.

## Session 2: Scoring Strategy Overhaul + LLM Fallback

### User Clarification on Scoring Strategy
User clarified the correct scoring approach:
- **Category** = fetch filter (determines which papers to consider)
- **Topic** = CORE scoring mechanism (LLM evaluates paper against topic descriptions)
- **Project** = BOOSTER only (provides floor guarantee, not score driver)

### Changes Made
1. **Rewrote `scorer.py`** with correct strategy:
   - LLM evaluates topic relevance (primary mechanism)
   - Project match provides small boost (+0.5 with LLM, +1.5 without)
   - Updated `prompts/match_preprint.md` to emphasize topic evaluation

2. **Fixed primary category filtering**:
   - Changed `check_category_match()` to only check paper's PRIMARY category
   - Cross-submissions (papers listed in our categories but with different primary) are excluded
   - Example: hep-ph paper cross-listed in astro-ph.CO is correctly excluded

3. **Added LLM fallback mechanism**:
   - `OpenAICompatibleClient` for KIMI/OpenAI/DeepSeek
   - `FallbackLLMClient` tries multiple providers in sequence
   - Config supports `llm_fallback` list

4. **Updated KIMI configuration**:
   - Model: `kimi-k2.5` (KIMI 2.5 released Jan 2026)
   - Endpoint: `https://api.moonshot.ai/v1`
