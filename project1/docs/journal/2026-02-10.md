# Development Journal - 2026-02-10

## Feature: RSS-Based arXiv Fetching

Branch: `feature/rss-arxiv-fetcher`

### Motivation

The existing Atom API fetcher (`export.arxiv.org/api/query`) sorts papers by submission date, not announcement date. This caused systematic misses due to:
- Weekend batching: papers submitted Friday, announced Monday (3-day gap)
- API indexing lag: newly announced papers not searchable for hours
- Observed: papers 2602.07114, 2602.07159, 2602.08312 appeared on arXiv "new listings" but were missed by the API fetcher

The arXiv RSS feed (`rss.arxiv.org/rss/{categories}`) lists papers by announcement date, matching the website exactly.

### Changes

1. **`pyproject.toml`**: Added `feedparser>=6.0` dependency, `pytest>=8.0` as dev dependency
2. **`src/arxiv_fetcher.py`**: Added 3 new functions (no existing code modified):
   - `parse_rss_description()` — regex extracts announce_type + abstract from description field
   - `parse_rss_entry()` — converts feedparser entry to `(ArxivPaper, announce_type)`
   - `fetch_papers_from_rss()` — single HTTP request, filters by type/category, deduplicates
3. **`src/main.py`**: Added `--source {rss,api}` CLI argument (default: `rss`), auto-switches to API when `--days` is specified
4. **`tests/test_rss_fetcher.py`**: 12 tests using saved RSS snapshot
5. **`tests/fixtures/rss_snapshot.xml`**: Captured 2026-02-10 RSS feed for deterministic testing

### Design Decisions

- **RSS as default**: Eliminates announcement-date gap. Single HTTP request is faster than 3 API calls with rate limiting.
- **Keep API as fallback**: RSS only has today's papers. `--days N` needs the API for historical lookback.
- **Auto-switch**: `--days` + RSS = auto-switch to API (logged). Users don't need to think about which source to use.
- **Filter by announce_type**: RSS includes `replace` and `replace-cross` (paper revisions). These are not new papers and must be excluded.
- **Additive approach**: No existing functions modified. All RSS code is appended to `arxiv_fetcher.py`.

### Results

- RSS: 114 entries total, 39 papers after type/category/dedup filtering
- Pipeline: 39 → 31 after local filter → 11 most relevant, 13 somewhat relevant, 7 could be interesting
- All 3 previously-missed papers (2602.07114, 2602.07159, 2602.08312) now appear in output
- 12/12 tests pass

### Regex Bug

Initial regex `\\?n` was intended to match a literal `\n` in the description string, but feedparser returns a real newline character. Fixed to `\s+` which matches any whitespace including newlines.
